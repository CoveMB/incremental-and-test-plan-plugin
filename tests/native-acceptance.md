## Authorization and native setup

Before any installation/configuration or model call, prepare a concrete local
packet for the selected surfaces and obtain explicit action authority. It must
name exact unused source/export/workspace/output/evidence paths, candidate hashes,
installed versions, proposed configuration diff and profile/collision handling,
model route and count, effective isolation/capture probes and recovery. Do not
commit private packets, personal paths, transcripts or local logs.

Use the [twelve-file inspected export](../docs/development.md#package-contents),
never the whole repository. Record SHA-256 for each selected file, and aggregate
by hashing sorted lines `file-sha256`, two spaces, relative path, newline. Verify
exact member paths and source-byte correspondence independently before and after
native staging/import. Any controlled fault candidate gets a distinct identity;
the immutable valid candidate remains intact throughout.

Setup routes are [documented in usage](../docs/usage.md#desktop-setup) and
[CLI setup](../docs/usage.md#cli-setup): Codex uses its verified native marketplace
identity; OpenCode uses the serving environment's merged skill-source entry;
Antigravity IDE uses one workspace plugin directory; Antigravity CLI uses its
local-plugin manager and inspected staged path. Preserve existing configuration,
permissions, installed copies and profile data. An occupied destination needs an
explicit update choice. No install, reload, profile flag or environment override
may be invented to bypass unsupported isolation. No remote-server transfer,
reinstall, broad permission change or optional-review invocation is implied.

D16 changes only a disposable candidate copy. D17/D18 deny skill/reference access
through supported native controls. D13–D15 use actual restricted coordination.
D19 uses two controlled conflicting copies through that host's supported discovery
route, with actual precedence recorded. D20 opens the nested project context.
Receivers and canaries must not inherit the plugin through global discovery.
Check both native skill visibility and actual loaded bodies/resources; plausible
answers or matching labels cannot establish candidate selection.

## Effective isolation and capture

Before semantic trials, prove the actual actor boundary using supported host-side
controls and synthetic sentinels: allowed candidate/fixture reads; denied private,
evaluator and sibling inputs; permitted selected planning writes; denied unrelated
writes, product/test execution, Git mutation, tool-network calls and recursive
delegation. Model transport itself is limited to the explicitly approved route.
Audit inherited instructions/memory/skills through supported inclusion metadata,
without exporting hidden or private instruction content. A fresh chat, a source
directive or a requested permission setting is not enforcement evidence.

Controller probes must exercise the actual actor permission profile and runtime
tool path, including overrides; a different shell sandbox proves no actor boundary.
If the surface cannot establish the necessary isolation or inspectable action
records, mark it blocked/unverified before semantic calls. Do not silently switch
to a CLI, desktop or source-read surface and claim acceptance for another one.

Each canary is one fresh actor with two permitted operations: read a synthetic
marker using an allowed utility, then run one allowed command with distinct stdout
and stderr markers and deliberate exit 7. Preserve exact arguments, both native
tool records/returns, actual exits and markers. Logger success or final response
text cannot establish capture. Failed canaries remain failures; no unchanged retry
for a better result. Bound each actor to ten minutes and at most 30 tool actions;
record stricter host limits before launch. Unexpected private input, unauthorized
write or candidate drift stops affected calls immediately.

## Order, outputs and grading

After successful preflight/canary, inspect native discovery and run D01–D03.
D10/D11/D13/D15 consume independent copies of actual D01 outputs. D21/D22/D23/D24
consume D01/D02/D03/D12 respectively. Missing required producer output blocks its
consumer. Incomplete output is preserved and evaluated as-is: never repair it,
insert template policy or supply omitted instructions before its receiver trial.
Keep raw fixture and before-images outside the actor's writable scope. Permit only
the selected planning outputs, or no writes for prompt-only/routing/decision and
receiver cases. Preserve source, human annotations, selected QA history and Git
state. Absolute producer references that cannot safely resolve block the consumer;
do not rewrite actual outputs to make the trial pass.

Each variant uses a fresh context/workspace. Extract only its raw request and full
required raw sources from the catalogue. Explicit invocation uses the verified
native identity; implicit routing receives no preloaded skill body. Optional
review inventory inspection does not invoke a review or establish its authority.
Grade producer coverage separately from receiver inference. A blocked attempted
forbidden action is not correct abstention. Denial controls, candidate conflicts,
missing resources and ordinary-use passes have distinct outcomes.

Keep exact prompts, candidate identities, versions/model route, discovery/UI or
terminal evidence, actual actions, errors, first outputs and before/after bytes
in local evidence outside tracked/shipped content. Retain native exit/status and
logger/capture status separately; mark incomplete/truncated capture. Report
observed/unrun/blocked cases against this selection, not only successful totals.

## Recovery and evidence limits

Before approved setup mutations, preserve affected settings' exact bytes/hashes
and original installed state, with an approved recovery action for each change.
Prefer new synthetic workspaces and supported isolated profiles; if a host needs
persistent global changes, first return their concrete diff and restoration plan.
An existing same-name plugin must not be overwritten automatically. Recovery may
close only trial sessions and return to the prior workspace while retaining trial
files/evidence, if approved. Verify discovery/state after recovery; do not call an
unperformed procedure rollback. Cleanup/removal/restoration over concurrent edits
needs its actual authority and surviving-evidence checks.

Static metadata, package closure, export controls and official documentation
establish source preparation only. Native installation, explicit/implicit routing,
resource access, actual coordination and output behavior need their own observed
results bound to surface/version/candidate. Other operating systems, headless
modes, Antigravity App, publication/provider workflows and unexercised native
capabilities remain outside demonstrated support. Preserve failures and accepted
history; renew only evidence affected by later source/environment changes.
